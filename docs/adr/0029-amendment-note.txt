> Amendment (owner, <date>), from SRV-INGEST revision 2 review rounds 4–5 and spikes/ingest-sysctl:
> - **The inode channel is open under every profile tried.** `fsgetpath()` on a directory's inode returns its path, and `chdir` into a known path is allowed, because both need only the global `file-read-metadata`; a metadata wall below the directory that holds all work directories does not stop them (measured, 2026-11-23). A confined child that scans the inode numbers near its own work directory finds a sibling run's.
> - **Decision 3's edits close the process channels only:** another process's arguments, environment, cwd and executable path, and the process lists (`kern.procargs2`, `kern.procargs`, `kern.proc.*`, `proc_pidinfo`, `proc_pidpath`, `proc_listallpids`). They do not close the inode channel.
> - **The control is one converter run on the host at a time.** Every converter run, the CLI's (`reader-ingest <material>`) and the watcher's alike, holds `<data_dir>/ingest/locks/convert.lock` from just before its run until its cleanup has ended; an idle watcher waits without it. So no run exists alongside another for a child to join. The CLI answers `busy` (exit 3) while an upload converts, and an upload queued during a CLI run waits, shown as `queued` with "a command-line conversion is running". Taking the lock cleans every run a crashed holder left.
> - **Residual: cross-run denial of service.** A child that escaped an earlier run (it called `setsid()`, left its work directory and rewrote its arguments, so it was neither counted nor killed) survives, still confined: no network, no sockets, no information about other processes, no writes outside a deleted directory. It can find each later run's work directory, join that run's accounting and push it over its 8 GiB memory limit, failing every later conversion until the Mac session restarts. There is no reliable signal, because the same argument rewrite hides it from the stray count; the symptom is repeated `memory_limit` failures on files that converted before, and the Import page names it with the remedy: restart the Mac session. A `sandbox_check(pid)` spike may later give a signal.
